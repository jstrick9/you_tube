# AIxploria Video Generator Audit for Archive 13

**Audit date:** 2026-10-13  
**Decision:** **Conditional go for a small, automated Runway Dev API bake-off of Gen-4.5 vs Veo 3.1 Fast as supplemental illustration only. Do not replace the current licensed-media pipeline or roll into production until the exact model route, account rights, output specification, and automated QA/disclosure controls below are verified.**  
**Status:** Research and recommendation only. No provider was configured, no clips were generated, and no pipeline or channel settings were changed by this audit.

## Executive recommendation

A current video model can add short, visually coherent inserts to a trend-qualified Archive 13 Short. It cannot find a live trend, establish what is true, supply original editorial value, or make a video viral. The strongest first path is **one Runway Dev API integration**, which now exposes both Runway Gen-4.5 and Google's Veo 3.1 / Veo 3.1 Fast. Run a small, automated bake-off between the two exact model IDs, then pin one model for any continued pilot; there is no need to add a second API integration just to compare them. Runway Dev's published no-audio rates are **$0.12/second for Gen-4.5** and **$0.10/second for Veo 3.1 Fast**. Runway's developer commercial-use guidance says commercial use is not restricted subject to its agreement and Usage Policy; verify that this applies to the specific account and hosted Veo route before publishing.

This is a **conditional, tightly capped test—not approval for automatic model routing, routine bulk generation, or an immediate production rollout**. Gen-4.5 portrait output is clearly documented at 720×1280, which needs upscaling for the channel's 1080×1920 master. Runway's Veo release notes advertise full 1080p, while the current API reference exposes 1280:720 / 720:1280 ratio values and an 8-second Veo example; resolve that documentation mismatch with a test request before counting on native 1080p or a particular duration. Runway's self-serve Terms of Use permit inputs/outputs to be used to train and improve models; its Enterprise commitments add contractual no-training and protections covering third-party models. Do not submit confidential material on self-serve, and confirm the account terms before production. Luma Ray 3.2 remains an attractive 720p price challenger with API-specific commercial terms to verify; Adobe Firefly remains enterprise-entitlement and contracted-price dependent.

Keep the existing live-trend evidence, sourced research, original narration, two approved content lanes (`history_mystery` and `science_nature`), automated visual QA, and final-render QA as hard gates. Use stylized or schematic inserts, not synthetic “archival footage,” invented real-person depictions, or fabricated scientific evidence. Preserve the Archive 13 promise: **“Every file is real. That's the problem.”**

### Important endpoint distinction

Google's Gemini Developer API, Google Cloud/Vertex AI, and Google's Veo models hosted through Runway Dev are **three distinct access/terms routes**. The direct Gemini API documents an 8-second preview-style Veo route and its own pricing/terms. Vertex/Cloud documentation lists a separate GA route with different durations, regions, pricing, and service terms; the Vertex model page also lists a retirement date of **2026-11-17 or later**. Runway Dev has its own platform rate card and terms for hosted Veo. In addition, Runway's Veo release note advertises 1080p but the current text-generation API schema exposes 1280:720 / 720:1280 ratio values and the Veo sample uses 8 seconds. Re-check the live schema and run a non-publishing smoke request before making a resolution/duration commitment. This audit does **not** combine the lowest price from one endpoint with the rights, availability, or output formats of another.

## 4. Monetization, disclosure, brand, and factuality risks

1. **Generator output is not trend evidence.** A topic must pass the repository's live trend gate first: current evidence, at least two independent trend families for corroboration, and freshness checks. Wikipedia is corroboration only; an anniversary or evergreen fact by itself does not qualify. A video model must never decide that a topic is currently trending or viral.
2. **AI visuals are not evidence.** For `history_mystery`, do not generate photorealistic “archival” scenes, purported historical photographs, named real people, or event-specific scenes that could be mistaken for source material. For `science_nature`, do not present a generated organism, experiment, landscape, or physical event as documentary evidence. Prefer conspicuously stylized, abstract, or schematic inserts, and use the existing licensed/source-backed material for factual proof.
3. **Apply YouTube's synthetic-content label when required.** YouTube requires disclosure for realistic AI-generated scenes that did not occur, altered footage of real events/places, and other covered realistic synthetic content. YouTube says disclosure itself does not limit monetization; repeated failure to disclose can lead to labels, content removal, or YPP penalties. Any integration must set disclosure automatically when the content meets the policy, preserve the asset's synthetic provenance, and fail closed if the state cannot be determined. Do not rely on a generic channel description as a substitute for the upload disclosure.
4. **Avoid “inauthentic content.”** YouTube's monetization policy disallows mass-produced, generic, repetitive, or low-value templated output; the channel-level review looks at substance and originality, not merely the rights to a model's output. Keep original reporting, narration, explanation, and materially varied story substance. Repeating a visual format is acceptable; repeating interchangeable substance is not.
5. **Rights are not performance guarantees.** A provider's commercial-use permission does not make a generated scene true, original in the copyright sense, non-infringing, or automatically eligible for YPP. Avoid real-person likenesses, logos, protected characters, prompts that imitate a specific creator or viral Short, and unlicensed references.
6. **Commercial permission and data use are separate.** Runway Dev's public guidance permits compliant commercial use, but its self-serve Terms of Use permit Runway to use inputs and outputs to train/improve models. Do not submit confidential material on self-serve. Runway's Enterprise terms add contractual no-training and data protections that explicitly cover hosted third-party models; verify which terms apply to this account. Google's direct Gemini API terms do not automatically govern Veo requests sent through Runway Dev. Runway's Terms also require “Powered by Runway” branding and a link in end-user apps that expose its API; that appears distinct from an internal publishing pipeline, but confirm applicability before any user-facing generation feature.
7. **Brand tension is real.** “Every file is real” is a strong factual promise. If an illustrative AI insert appears, its style and context must make clear it is an illustration, not a real archive file. Do not use realistic fake footage to manufacture mystery or proof.

## 5. Proposed automated pilot (not yet run)

**Provider:** One Runway Dev API project; call the exact model IDs `gen4.5` and `veo3.1_fast`, not an automatic Model Router. Before using any output in a published Short, verify the applicable commercial-use terms, the actual Veo dimensions/duration, and the account's data-use terms. If those checks fail, do not publish generated footage.

**Scope:** Four currently trend-qualified Shorts—two in `history_mystery` and two in `science_nature`—with one illustrated shot prompt per Short. Generate one 5-second Gen-4.5 candidate and one Veo 3.1 Fast candidate per prompt (use the documented 8-second Veo example for the budget; trim to the editorially needed length). That is **8 model outputs total** for four shots; choose at most one passing clip per Short. Keep original narration, factual sourcing, music, editorial structure, and current licensed visual search. Generated footage is supplemental; it must not displace a relevant licensed/source asset.

**Cost:** Four Gen-4.5 5-second outputs × $0.12/second = **$2.40**; four Veo 3.1 Fast 8-second outputs × $0.10/second = **$3.20**; estimated one-pass comparison total **$5.60**, before tax. If the Runway Veo route accepts 5-second outputs, that portion would be $2.00 instead; do not assume this until verified. Do **not** reroll in this initial bake-off: failed or QA-rejected candidates fall back to the existing media search. Runway Dev requires a **$10 minimum credit purchase**, so this one-pass test fits within the initial credit purchase. Set a hard project budget and do not permit unbounded retries.

**Automated gates:**

- Generate only after the live-trend evidence passes and the script is original, source-grounded, advertiser-safe, and in an approved lane. If there is no current qualifying topic, generate nothing.
- Use prompts for obviously illustrative motion/visual metaphors. No realistic archival simulation, historical figure, real accident/disaster reenactment, fabricated scientific “proof,” celebrity, or third-party style imitation.
- Save the exact provider/model/version, prompt, task ID, timestamp, duration/resolution, API terms snapshot/version, per-task cost, file hash, and synthetic flag with the asset's provenance.
- Reuse the existing automated visual match checks and final-frame QA. Add machine-enforced checks for dimensions, duration, decode/render integrity, artifacts, visual-narration relevance, and the synthetic disclosure state. Apply identical QA to both model outputs and select only a passing clip using a predeclared automated score; if both pass comparably, use cost as the tie-breaker. If neither passes, fall back to the existing licensed-media search; if the video still cannot pass current visual/factual gates, skip that topic rather than publish an unverified render. **No human-approval step is proposed.**
- Keep the finished 1080×1920 Short, original narration, and non-generated visuals as the majority of the work. Check Gen-4.5's 720×1280 upscale and verify the actual Veo dimensions before deciding it is a substitute.
- Evaluate the pilot as a production/quality test first. Once audience data is available, compare the channel's average-view percentage and retention curve against the internal **70% average-view target**, alongside engaged views and costs. Four videos are too small to establish causation; no views, retention level, virality, or monetization outcome is guaranteed.

### Stop/continue criteria

Continue only if the selected model's account terms and schema are verified; every published clip clears factual relevance, artifact, rights/provenance, disclosure, render, and final QA checks; output dimensions meet the 1080×1920 master requirement (including any acceptable upscale); and the spend cap is respected. If neither Runway model passes, keep the existing source pipeline; consider Luma or a direct Google API only as a separately reviewed provider route with its own terms and cost cap. Do not broaden to bulk generation or all-in-one script-to-video tools on the basis of this pilot.

## 6. Current repository fit and change status

The current workflow in `autotube/pipeline.py` is trends → research/grounding → script/review → TTS → visuals → render → final QA → upload. `autotube/media.py` currently sources licensed/public-domain material from Wikimedia Commons, NASA, Pexels, Openverse, and configured archive sources, then checks candidates against the narration. `autotube/qa.py` checks rendered frames against narration and intended shots. The config has no generative-video API provider enabled; `contains_synthetic_media` defaults to `false`, and the existing Pixazo image helper is suppressed while that flag is false. This is a useful fail-closed baseline, but a future video adapter would need per-video provenance and automatic disclosure handling rather than simply changing the global flag.

**No code was integrated as part of this audit.** The report is a recommendation and implementation specification; production behavior remains unchanged.
